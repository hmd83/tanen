# **2\. Project Overview**

TanenBase is an ultra-low-power IoT end-node designed for remote, unattended beehive monitoring. Each node is deployed inside or beneath a beehive and continuously measures hive weight, internal temperature, and battery voltage. Collected data is transmitted over the LoRaWAN network to a cloud server for remote analysis and alerting.

The system is engineered for extreme power efficiency, enabling multi-year operation on a single battery charge. A Finite State Machine (FSM) governs all operational modes, ensuring that the sensor sampling schedule is fully decoupled from the radio transmission schedule. Both timers are remotely configurable via LoRaWAN downlink or locally via Bluetooth (BLE).

## **2.1 System Goals**

* Continuous, unattended monitoring of hive weight, temperature, and battery voltage.

* Ultra-low-power operation — less than 20 µA in sleep state.

* Immediate anomaly alerting for sudden weight loss (swarm detection or theft).

* Remote parameter configuration via LoRaWAN downlink and local BLE.

* Robust, binary-encoded LoRaWAN uplinks with 4-byte payload.

* Reliable OTAA network joins on the EU868 frequency plan.

## **5.4 Downlink Command Format**

Class A RX1/RX2 after every uplink. One field per downlink (FPort selects field). User may send any subset.

| FPort | Field | Bytes | Encoding |
| :---- | :---- | :---- | :---- |
| **10** | T\_TX (`tx_interval`) | 4 | uint32 BE, seconds |

| **12** | anomaly weight threshold | 2 | uint16 BE, grams |
| **13** | anomaly temp threshold | 2 | uint16 BE, °C × 100 |

Wrong length → ignored (warning logged). Values persisted to ZMS on receipt.

# **6\. Payload Specification**

The uplink payload is exactly 4 bytes. No padding, headers, version bytes, or metadata are permitted. The server (TTN Payload Formatter) is solely responsible for decoding raw values back to human-readable units.

## **6.1 Payload Map**

| Byte(s) | Field |
| :---- | :---- |
| **Byte 0–1 (uint16, big-endian)** | Weight — raw value \= kg × 100\. Range: 0–65535 (max 655.35 kg). Example: 45.23 kg → 4523 |
| **Byte 2 (uint8)** | Temperature — raw value \= °C rounded to nearest integer. Range: 0–255. Example: 36°C → 36 |
| **Byte 3 (uint8)** | Battery Voltage — raw value \= V × 10\. Range: 0–255 (max 25.5 V). Example: 12.4 V → 124 |

## **6.2 Payload Encoding Rules**

* Total payload length: exactly 4 bytes. Never more, never less.

* Weight field: multiply float kg value by 100, cast to uint16, pack as big-endian.

* Temperature field: round float °C value to nearest integer, cast to uint8.

* Voltage field: multiply float V value by 10, cast to uint8.

* Fields must be packed in the order: Weight (2B), Temperature (1B), Voltage (1B).

* No null bytes, no struct padding, no alignment bytes between fields.

* JSON, CSV, or ASCII text payloads are prohibited and constitute a firmware defect.

## **6.3 TTN Payload Decoder (Reference JavaScript)**

function decodeUplink(input) {

  var b \= input.bytes;  
  return { decoded\_payload: {  
    weight\_kg:  ((b\[0\] \<\< 8\) | b\[1\]) / 100.0,  
    temperature\_c: b\[2\],  
    voltage\_v:   b\[3\] / 10.0  
  }};

}

# **7\. Cycle Control & Power Management**

The sensor measurement schedule and the LoRaWAN transmission schedule are fully independent. Two configurable timers govern system wake cycles.

## **7.1 Timer Parameters**

| Parameter | Specification |
| :---- | :---- |
| **T\_MEAS** | Measurement Timer — minimum 1 minute. Configurable remotely via LoRaWAN downlink or BLE. |
| **T\_TX** | Transmission Timer — must satisfy: T\_TX ≥ T\_MEAS at all times. |
| **Remote Config** | Both timers are remotely adjustable via LoRaWAN downlink command or BLE Setup Mode. |
| **Constraint Enforcement** | Firmware must reject any downlink that sets T\_TX \< T\_MEAS and respond with a NACK. |
| **Default T\_MEAS** | 15 minutes (900 seconds) |
| **Default T\_TX** | 60 minutes (3600 seconds) |

## **7.2 Measurement Routine**

* Wake processor from deep sleep.

* Power up load cell (NAU7802) and DS18B20 .

* Acquire N consecutive weight samples (default N \= 10\) at regular intervals.

* Compute arithmetic mean weight; discard outliers exceeding ±2σ to suppress wind noise.

* Acquire single temperature reading from DS18B20.

* Acquire single battery voltage reading via internal ADC.

* Compare new mean weight to last stored weight; check for anomaly threshold breach.

* Store all readings in SRAM (latest snapshot only — no historical buffer required).

* Power down all sensors immediately after data acquisition.

* Transition to FSM State 4 (Active Sleep) or State 3 (Transmission) based on anomaly flag.

## **7.3 Transmission Routine**

* Wake processor from deep sleep.

* Load latest sensor snapshot from SRAM.

* Encode 4-byte binary payload per Section 6 specification.

* Power up SX1262 LoRa radio via SPI.

* Transmit uplink on next available channel (duty cycle compliant).

* Hold radio active for RX1 window (1 second delay) and RX2 window (2 seconds delay) to receive downlink.

* Process any received downlink configuration commands.

* Power down SX1262 radio (all GPIO lines low, SPI bus released).

* Return to FSM State 4 (Active Sleep).

## **7.4 Emergency Anomaly Override**

| Parameter | Specification |
| :---- | :---- |
| **Trigger Condition** | New mean weight \< (last stored weight − anomaly threshold) |
| **Default Threshold** | 2.0 kg (200 raw units). Configurable via downlink or BLE. |
| **Action** | Abort T\_TX wait. Immediately enter State 3 (Transmission).  LED blink |
| **Uplink Type** | Confirmed uplink used for anomaly alerts to guarantee delivery. |
| **Alert Payload** | Standard 4-byte payload — server infers anomaly from weight delta via TTN decoder. |

# **8\. Finite State Machine (FSM)**

The firmware implements a strict four-state FSM. No state may be entered except through its defined entry conditions. All transitions are deterministic.

| State 1: Setup Mode (BLE) |  |
| :---- | :---- |
| **Entry** | Initial device boot OR TanenButton held for ≥3 seconds. |
| **LED State** | solid ON throughout Setup Mode. |
| **BLE** | Activate Bluetooth LE. Advertise as 'TanenBase-XXXX' (last 4 hex of DevEUI). |
| **Web App** | Serve configuration interface via connected BLE client (HTML \+ JS web app one file index.html). |
| **Config Items** | LoRaWAN credentials (JoinEUI, DevEUI, AppKey), T\_MEAS, T\_TX, anomaly threshold, scale calibration (zero offset, scale factor) \-read(expt AppKey  )-write(save). |
| **Live Feed** | Broadcast real-time sensor data over BLE NOTIFY characteristic for scale tare/calibration. |
| **Test Join** | Execute LoRaWAN OTAA test join on user request from web app. Report result (Blink 1Hz \= OK, fast= fail). |
| **Exit — Normal** | Exit button in web app . BLE advertisement stopped. Transition to State 4\. |
| **Exit — Timeout** | 5-minute inactivity timeout reached without user interaction. BLE stopped. Transition to State 4\. |

| State 2: Measurement State |  |
| :---- | :---- |
| **Entry** | T\_MEAS timer expiration in State 4\. |
| **LED State** | No LED activity during measurement (power conservation). |
| **Sensor Power** | Wake up NAU7802 and DS18B20 .NAU7802 requires time 600ms  to stabilize |
| **Weight Acquisition** | Capture N \= 10 samples from NAU7802 ADC. Compute filtered mean weight (kg). |
| **Temp Acquisition** | Issue single read command to DS18B20. Store integer °C value. |
| **Voltage Acquisition** | VBAT Enable pin then Sample internal ADC on voltage-divider channe(P1.13 AIN6\_VBAT)l. Store (V × 10\) uint8 value. |
| **Anomaly Check** | If (new weight) \< (last weight − threshold): set ANOMALY flag. |
| **Data Save** | Update SRAM sensor snapshot with new values. |
| **Exit — Anomaly** | ANOMALY flag set → transition immediately to State 3 (Transmission). |
| **Exit — Normal** | No anomaly → transition to State 4 (Active Sleep). |

| State 3: Transmission State |  |
| :---- | :---- |
| **Entry** | T\_TX timer expiration in State 4 OR ANOMALY flag set in State 2\. |
| **LED State** | LED — blinks once per transmit attempt. blinks fat — lit on join failure or anomaly uplink. |
| **Payload Build** | Encode 4-byte binary payload: bytes \[0:1\] \= weight × 100 (uint16 BE), byte \[2\] \= temp (uint8), byte \[3\] \= voltage × 10 (uint8). |
| **Radio Power** | Assert SPI CS and power enable for SX1262. |
| **Transmit** | Send uplink frame (unconfirmed normally; confirmed if ANOMALY flag set). |
| **RX Windows** | Wait for RX1 ( 5 s window) and RX2 (6 s window). Process any downlink. |
| **Downlink Handling** | Apply new T\_MEAS, T\_TX, or anomaly threshold from downlink. Validate T\_TX ≥ T\_MEAS. |
| **Radio Power Down** | De-assert all SX1262 control lines. Release SPI bus. |
| **Clear Flag** | Clear ANOMALY flag. |
| **Exit** | Always transition to State 4 (Active Sleep). |

| State 4: Active Sleep State |  |
| :---- | :---- |
| **Entry** | Completion of State 1, State 2, or State 3\. |
| **LED State** | All LEDs OFF. |
| **Sensor Power** | NAU7802 powered down (AVDDS=1, PUA=0 \-\> \~0.1 uA)-powered down DS18B20 I2C pins during low-power modes, they should generally be configured as inputs (high-impedance) or as outputs driven high to avoid leaking current through external pull-up resistors |
| **Radio Power** | SX1262 in SLEEP mode. SPI bus idle. BLE radio disabled. |
| **MCU Sleep** | nRF54LM20A enters System OFF \+ GRTC \+ RAM retention (stack \+ essentials) |
| **Power Budget** | Total system current draw: ≤ 20 µA. |
| **Timer Operation** | Both T\_MEAS and T\_TX GRTC  timers continue running during sleep . |
| **Exit — T\_MEAS** | T\_MEAS expires first → wake to State 2 (Measurement). |
| **Exit — T\_TX** | T\_TX expires first → wake to State 3 (Transmission). |
| **Exit — Button** | TanenButton pressed → wake to State 1 (Setup Mode). |

# **9\. FSM State Transition Summary**

| From State | Event | To State | Condition |
| :---- | :---- | :---- | :---- |
| State 4 (Sleep) | T\_MEAS expires | State 2 (Measurement) | Normal measurement cycle |
| State 4 (Sleep) | T\_TX expires | State 3 (Transmission) | Normal transmission cycle |
| State 4 (Sleep) | TanenButton pressed | State 1 (Setup) | User-initiated configuration |
| State 2 (Measurement) | No anomaly detected | State 4 (Sleep) | Normal exit |
| State 2 (Measurement) | Anomaly flag set | State 3 (Transmission) | Emergency override |
| State 3 (Transmission) | Transmission complete | State 4 (Sleep) | Always |
| State 1 (Setup) | Config saved | State 4 (Sleep) | Normal exit |
| State 1 (Setup) | 5-min inactivity | State 4 (Sleep) | Timeout exit |
| Any State | TanenButton (3 s hold) | State 1 (Setup) | From sleep only; immediate boot entry always |

# **10\. Power Budget**

| System Mode | Target Current Draw |
| :---- | :---- |
| **State 4 — Active Sleep (MCU deep sleep, all peripherals off)** | ≤ 20 µA (absolute maximum) |
| **State 2 — Measurement (sensors powered, ADC active)** | \< 15 mA peak |
| **State 3 — LoRa TX (SX1262 transmitting at \+14 dBm)** | ≈ 120 mA peak (limited duration) |
| **State 3 — LoRa RX window** | ≈ 5 mA |
| **State 1 — BLE advertising** | ≈ 3–5 mA |
| **Target Battery Life** | \> 12 months on 3.6 V / 19 Ah Li-SOCl2 primary cell (typical deployment) |

## **10.1 Power Management Rules**

* SX1262 must be commanded to SLEEP mode before the nRF54LM20A enters deep sleep.

* BLE radio must be fully disabled before entering State 4\.

* No floating GPIO pins that could increase leakage current above the 20 µA target.

# **13\. Non-Functional Requirements**

## **13.1 Reliability**

* LoRaWAN OTAA join must be retried up to 8 times with exponential backoff on failure.

* If OTAA join fails after all retries, the device must enter State 4 and retry at next T\_TX interval.

* Watchdog timer must be active at all times. WDT timeout: 60 seconds.

* All NVS write operations must be atomic — partial writes must not corrupt configuration.

## **13.2 Environmental**

* Operating temperature: \-20°C to \+60°C (outdoor beehive deployment).

* Humidity: 95% RH non-condensing.

* All connectors must be weatherproofed. Enclosure minimum IP65.

## **13.3 Security**

* AppKey must never be logged to serial/debug output.

## **13.4 Regulatory**

* EU868 duty cycle limits (1% per sub-band) must be enforced in firmware via LoRaWAN stack.

* RF output power must not exceed \+16 dBm EIRP (EU868 limit).

* Device must comply with CE marking requirements for short-range radio devices (EN 300 220).

# **Deviations from this TRD (as-built)**

The firmware in this repository intentionally departs from the draft above.
These are design decisions, not defects.

| Area | TRD says | As built | Why |
| ----- | ----- | ----- | ----- |
| **Uplink payload** | 4 bytes | **8 bytes**: weight u24 g (0-999000), temp i16 centi-degC, battery u16 mV, flags u8 | u16 grams topped out at 65.535 kg, well under a loaded hive. Sentinels `0xFFFFFF` / `0xFFFF` / `0x7FFF` mark a failed sensor and decode to `null`. |
| **T\_TX timer** | Second hardware timer | Heartbeat **modulo** of measurement cycles (`meas_count % (tx_interval/ms_interval)`) | One GRTC wake source instead of two; no second timer to keep alive through System OFF. |
| **Uplink policy** | Fixed confirmed-uplink rules | Delta-based TX with an anomaly ladder (`src/drivers/lora.c`) | Sends on change, not on schedule \- large airtime and energy saving. |
| **DevNonce** | Not specified | Monotonic counter persisted in ZMS (ID 1), hard-fail if it cannot be written | A repeated nonce is replay-rejected by TTN, which bricks joins until the device is re-registered. |
| **Credential GATT writes** | Encrypted pairing required (12.1) | Plain read/write | Web Bluetooth has no `pair()` API; an OS-triggered SMP pairing mid-write hung the link to supervision timeout. Confidentiality now rests on BLE proximity. Tried and reverted 2026-07-07 \- see `OPEN_QUESTIONS.md` item 10. |
| **Watchdog** | 120 s, production only | `task_wdt` 60 s channel \+ `wdt31` hardware fallback, **all** builds | Meets AC-10 with margin and catches kernel/timer death, not just main-loop stalls. |
| **Battery monitor** | Voltage divider \+ SoC ADC | nPM1300 VBAT ADC | The LM20A module carries the PMIC; its ADC is factory-trimmed, so the divider and its calibration factor are gone. |
| **Storage** | NVS, 4 KB | **ZMS**, 36 KB at 0x1D1000 (pinned in `pm_static.yml`) | `settings_zms` is unreliable on nRF54L RRAM, so `config.c` drives ZMS directly. The address is pinned so an app-size change or MCUboot adoption cannot relocate it and wipe the DevNonce. |
